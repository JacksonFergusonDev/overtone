## State of the project

- Version `0.1.0` (unreleased). All five roadmap phases are implemented: the CLI, quality analysis, sync to Serato, Rekordbox (XML and My Tags in `master.db`), and Traktor, and the desktop app. Phase 6 (metadata provenance and lookup, ffmpeg, and format conversion) is built through step 8a in the CLI and desktop app; relocation (8b) is next after the manual pass ([Phase 6 plan](engineering/plans/metadata-and-conversion.md)). None of it has been checked inside real DJ apps or in a real app window yet (see Unresolved).
- **Library and scanning:** in-place indexing of library folders, incremental rescans, missing-file tracking, and audio-only BLAKE3 hashes for duplicate detection ([content hashing](engineering/decisions/content-hashing.md)). Tag and stream property reading via `lofty` 0.25.5. On the `local/` testing ground, 1,151 files scan in about 9 s cold and rescan in milliseconds.
- **Quality analysis:** analyzer version 2: single-pass `symphonia` decode, with ffmpeg as a fallback decoder, loudness, true peak, clipping, and leading-silence measurements in the same pass (about doubling a first audit), and an opt-in ffmpeg integrity check (`audit --integrity`), with Welch-averaged spectra, cutoff wall detection, verdicts, waveform peaks, and spectrogram PNGs ([audio quality analysis](engineering/decisions/audio-quality-analysis.md)). On `local/`: 1,092 pass, 39 warning, 15 suspect, 5 inconclusive, in 238 s on 4 threads with loudness (105 s without).
- **Tag writing:** verified Comment and field writes for MP3, WAV, AIFF, and FLAC by a byte-level splicer (Phase 6 step 1) that keep Serato GEOB, Traktor PRIV, and artwork byte-identical and preserve the ID3 version; refuses files its walkers can't fully account for ([tag writing](engineering/decisions/tag-writing.md)). M4A writes are deferred.
- **Serato sync:** lossless `.crate` codec (all 140 sample crates round-trip byte-identically), dry-run plans, backups, and atomic writes under an `Overtone` root crate.
- **Rekordbox XML:** `rekordbox.xml` written with `quick-xml` (not `rbox`, see [DJ software sync](engineering/decisions/dj-software-sync.md#rekordbox-xml-written-with-quick-xml-not-rbox)): an `Overtone` playlist folder mirroring the vibe tree, stable TrackIDs, percent-encoded `Location` URIs from raw path bytes, no cue or beatgrid data, backups, and unchanged-file detection.
- **Rekordbox My Tags:** each vibe becomes a My Tag in an `Overtone` category of `master.db`, written by Overtone's own SQLCipher code rather than `rbox` (it can't share a build with `rusqlite` 0.43, see [DJ software sync](engineering/decisions/dj-software-sync.md#rekordbox-masterdb-own-my-tag-writer-over-rusqlite-with-sqlcipher-not-rbox)). The live database is never opened: a copy is edited, verified (integrity, foreign keys, every row outside the category unchanged, update counter), and swapped in with the stale WAL parked first. Tested on a copy of the real 7.0.8 database (`OVERTONE_RB_FIXTURE`, opt-in).
- **Traktor:** byte-preserving splice of an `Overtone` folder into `collection.nml` ([design](engineering/decisions/dj-software-sync.md#traktor-splice-the-overtone-playlist-folder-into-collectionnml)), tested on synthetic TP3 and TP4 fixtures; there is no Traktor install or real collection here.
- **Desktop app:** 48 Tauri commands over core ([desktop UI plan](engineering/plans/desktop-ui.md)) with progress channels, a runtime asset scope for library folders, and a spectrogram cache. The React UI ([frontend stack](engineering/decisions/architecture-and-ui.md#frontend-stack)) has a virtualized library table, a player with a canvas waveform, a quick-tag palette, a spectrogram inspector with review actions, a needs-review flow, a track details panel (loudness, integrity, field sources, suggestion review, export, and FLAC conversion), a Sync view for every sync target, and Settings for folders, scans, audits, lookup keys, integrity checks, and batch conversion. `pnpm --dir app dev` runs it in a browser against a seeded mock backend. An IPC test runs commands through Tauri's real ACL on the mock runtime.
- **Metadata provenance and lookup:** every field has a source (file, user, or accepted lookup); `meta lookup` queries MusicBrainz, AcoustID, and Discogs and adds only pending suggestions ([lookup](engineering/decisions/metadata-lookup.md)) ([Phase 6 plan, step 2](engineering/plans/metadata-and-conversion.md#step-2-per-field-metadata-provenance)). In the CLI and desktop app; exports use the effective values, and `meta apply` writes them into files through the verified splicer for the 11 fields the scanner reads ([field writes](engineering/decisions/tag-writing.md#field-writes)).
- **ffmpeg:** `overtone-ffmpeg` runs ffmpeg as a child process (locate, PCM decode over a pipe, integrity checks, encode jobs with progress and cancel); lossless decodes match Symphonia bit for bit ([decision](engineering/decisions/ffmpeg.md)). Development uses Homebrew's ffmpeg; the bundled build is not made yet.
- **Lossless conversion:** `convert` writes verified FLACs beside WAV/AIFF originals with tags, artwork, and Serato data; they wait for relocation (step 8b) and scans skip them ([decision](engineering/decisions/lossless-conversion.md)).
- **Export copies:** `export` writes CDJ-safe AIFF, AAC, MP3, FLAC, or WAV copies, verified by Symphonia before they land, never replacing a file.
- **CLI:** `status`, `roots`, `scan`, `ls`, `show`, `vibe`, `meta`, `export`, `convert`, `audit`, `review`, `spectrogram`, `tag mirror|restore`, and `sync serato|rekordbox|rekordbox-tags|traktor`, all with `--json`.

## Unresolved

- **Manual checks pending:** real DJ app behavior (Serato DJ 4 accepting written crates, Rekordbox importing the XML and opening a database with Overtone's My Tags, Traktor loading the patched collection, cues surviving Comment writes), listening to the 15 flagged suspects, and the desktop app in a real window (WKWebView playback of FLAC and AIFF, layout at 840x560, keyboard flow). The UI has only been exercised in a browser against the mock backend. All of them are in the [manual verification checklist](engineering/manual-verification.md).
- **Detection limits:** LAME V0 and 256k AAC transcodes can't be detected from the spectrum alone; an MDCT/frame-alignment detector would be needed. HE-AAC, Opus, WMA, and files Symphonia can't read are analyzed through ffmpeg when it's installed (analyzer version 2).
- **Integrity check findings:** on `local/`, 16 files have decode errors inside the music, 14 of them MP3s with `bits_left` warnings whose audibility is unknown (listening check on the checklist).
- **Tag write refusals:** after the byte-level splicer, 15 of 1,082 writable files on `local/` are still refused: 7 WAV files with two ID3 chunks, 3 unsynchronised and 1 experimental MP3 tag, and 4 files lofty can't read at all ([tag writing](engineering/decisions/tag-writing.md#files-a-write-refuses)).
- DJ app running detection uses `sysinfo` process matching. The Rekordbox, `rekordboxAgent`, and Traktor Pro 3 process names are unverified against real installs.
- **Unverified sync assumptions:** how Rekordbox Cloud Library Sync treats rows Overtone adds, and Traktor's mapping of `/Volumes/<Drive>` paths to `VOLUME`. Both are on the checklist.
- **Desktop app rough edges:** playback stops at the end of a track instead of continuing; sidebar vibe counts are direct only; Serato sync and Comment mirroring always use the default target (no folder or vibe picker); a removed library folder stays playable until restart.
- `rbox` (`0.3.1`) macOS SQLCipher build flags need verification when Phase 5 (`master.db` write support) begins.

## Next

How the work runs: before each feature, a research subagent surveys crates; contested choices get spikes and benchmarks on the M3 (recorded in `engineering/decisions/`). Implementation packages run in parallel git worktrees under `.claude/worktrees/` with written contracts (owned files, API, tests, spikes), Opus for risky or subtle work and Sonnet for well-specified work. The main session reviews each diff, merges with `--no-ff`, integrates into core and the CLI, verifies against `local/`, and adds manual checks to the checklist.

Phase 6 is the current work. Follow the [Phase 6 plan](engineering/plans/metadata-and-conversion.md) in order and mark each step done there and here as it lands. Its key rules: provenance (step 2) lands before any lookup (step 5) so fetched values never mix with the DJ's own; OneTagger is a source of ported ideas and code, not a dependency; ffmpeg runs as a bundled child process and Symphonia verifies its output.

1. Run the field-write check on `local/` clones for the five release-detail fields (catalog number, ISRC, release date, track and disc numbers; reader version 2, migration 0008), as done for the first 11 fields ([plan](engineering/plans/metadata-and-conversion.md#desktop-surfaces-for-phase-6)).
2. The manual verification pass ([checklist](engineering/manual-verification.md)), on throwaway DJ libraries, then fix what it turns up. It must happen before step 8b.
3. Step 8b: conversion relocation in DJ apps, one app at a time. Which app goes first is undecided.
4. Desktop polish: continuous playback, a target picker for Serato, Comment mirroring, and Traktor collections, and Traktor `INFO/@COMMENT` hashtag mirroring (noted in [vibe tags](engineering/decisions/vibe-tags.md)).
5. Release packaging: signing, notarization, building and bundling the audio-only ffmpeg sidecar ([configuration](engineering/decisions/ffmpeg.md#the-bundled-build-for-release-packaging)), and Homebrew/GitHub release automation.
